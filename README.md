# The Crowdsourced Festival Stage Optimizer

PostgreSQL replaces the human DJ. The crowd votes on their phones, a trigger keeps a sliding-window vibe score under a strict two-phase lock, and when the score falls to the threshold a stored procedure rewrites the stage's queue with an adjacent vibe. Node and React only carry messages.

See [CHANGES.md](CHANGES.md) for what changed from the first version and why.

## Project layout

```
db/schema.sql                   tables, keys, CHECK constraints (3NF)
db/triggers_and_procedures.sql  autopilot: triggers, procedures, views
db/seed.sql                     generated by ml/cluster_tracks.py
ml/cluster_tracks.py            offline K-Means clustering -> seed.sql
backend/server.js               thin REST relay (Express + pg)
backend/load_test.js            1,000 concurrent votes + lost-update check
frontend/                       React (Vite): audience view and /admin
```

## Option A: run everything with Docker (recommended)

You need Docker Desktop running.

```bash
git clone https://github.com/anushkasrivastava21/festival-stage-optimiser.git
cd festival-stage-optimiser
docker compose up --build
```

Then open:

- Audience view: http://localhost:5173
- Admin view: http://localhost:5173/admin

A ready-made `db/seed.sql` (1,200 demo tracks in 6 vibes) is included, so you do not need Python for the first run.

To open the audience view on phones, connect them to the same Wi-Fi as the laptop and visit `http://<laptop-IP>:5173` (find the IP with `ipconfig` on Windows or `ifconfig` on macOS/Linux).

If you change any `.sql` file, reset the database, because Postgres only runs the init scripts on an empty volume:

```bash
docker compose down -v
docker compose up --build
```

## Option B: run without Docker

Requirements: PostgreSQL 15+, Node.js 20+, Python 3.10+ (only for re-clustering).

1. Create and load the database:

   ```bash
   createdb -U postgres festival_db
   psql -U postgres -d festival_db -f db/schema.sql
   psql -U postgres -d festival_db -f db/triggers_and_procedures.sql
   psql -U postgres -d festival_db -f db/seed.sql
   ```

2. Start the backend (terminal 1):

   ```bash
   cd backend
   npm install
   # only if your Postgres password is not "postgres":
   # Windows PowerShell: $env:DATABASE_URL="postgres://postgres:YOURPASS@localhost:5432/festival_db"
   # macOS/Linux:        export DATABASE_URL=postgres://postgres:YOURPASS@localhost:5432/festival_db
   npm start
   ```

3. Start the frontend (terminal 2):

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

   Open http://localhost:5173 and http://localhost:5173/admin.

## Re-generating the catalogue with the ML step (optional)

```bash
cd ml
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS/Linux
pip install -r requirements.txt

python cluster_tracks.py                              # synthetic demo catalogue
python cluster_tracks.py --csv dataset.csv --limit 3000   # real Kaggle data
```

For real data, download a Spotify audio-features CSV from Kaggle (for example "Spotify Tracks Dataset", which has `track_name`, `artists`, `duration_ms`, `energy`, `valence`, `danceability`, `tempo`, `acousticness`, `loudness`). The script overwrites `db/seed.sql` and writes `ml/cluster_report.txt` with the centroids and silhouette score for your report. Then reset the database (`docker compose down -v && docker compose up --build`, or re-run the three `psql` commands on a fresh database).

## Running the demo

1. Open the audience view on a phone or a second browser window, and the admin view on the laptop.
2. Tick "Play the stage sound on this device" on the one screen connected to speakers.
3. Tap "Hate this vibe" a few times and watch the score move on both screens.
4. Run the load test (terminal 3, backend must be running):

   ```bash
   cd backend
   node load_test.js 1000 1 0.9
   ```

   Arguments are: number of votes, stage id, share of downvotes. It prints `PASS: zero lost updates.` when the counter kept by the trigger equals the number of rows inserted. With 90% downvotes the score crosses -50 and the admin decision log shows the autopilot pivot.
5. Tick "Manual override" in the admin view and run the load test again: the score drops but the vibe stays, because the trigger respects the override. Use "Force a vibe" to switch by hand.

## Useful SQL for the viva

```sql
SELECT * FROM v_stage_stats;                        -- live score, counters, override
SELECT * FROM v_shift_log ORDER BY created_at DESC; -- every autopilot decision
CALL sp_force_vibe(1, 5);                           -- manual pivot to cluster 5
EXPLAIN ANALYZE SELECT SUM(vote_val) FROM live_votes
 WHERE stage_id = 1 AND vote_time > now() - interval '60 seconds';  -- uses idx_votes_stage_time
```

Tuning lives in the `stages` table: `threshold` (default -50), `window_seconds` (60), `cooldown_seconds` (20), `play_seconds` (30 per track).
